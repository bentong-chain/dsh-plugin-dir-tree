# dsh-plugin-dir-tree

[简体中文](README.md) | **English**

> A DeepSeek Harness (DSH) plugin that shows a floating directory tree of the **current workspace**, with drag-and-drop paths into the chat box, double-click to copy, search filtering, and lazy loading.

> 🚀 **Want to install directly? Use the standalone distribution**: [dsh-dir-tree](https://github.com/bentong-chain/dsh-dir-tree) (Form-C standard bundle, install via `dsh plugin add`)

## Features

- 📁 Floating directory tree of the workspace, minimizable at the bottom-right corner
- 🌲 Lazy loading: click `▶` to expand subdirectories, avoiding freezes on large directories
- 🖱️ Drag files/folders into the chat box; the full path is filled in automatically
- 📋 Double-click to copy a path; single-click to select
- 🔍 Search filter for file names
- 🎨 File-type icons + directory 📁/📂 blue highlight + indented tree lines
- 🪟 Draggable floating window position

## Three Forms

This repository offers three forms — pick whatever fits:

| Form | Description | Pros | Cons |
|------|------|------|------|
| **C — Standard bundle** (`bundle/`) ⭐ Recommended | Single npm package, install with `dsh plugin add` | Standard distribution; no checkout/build/Creator mode needed | Needs publishing to npm or git |
| **A — Dynamic plugin** (`dynamic/`) | Self-contained JS code | Works out of the box | Must be re-run after restart + requires Creator mode |
| **B — Persistent plugin** (`persistent/`) | Domain package + UI package source | Auto-loads on restart | Requires editing api-remotes + building inside a DSH source checkout |

### ⚠️ First check how your DSH is installed

| Installation method | Which form to use |
|---------|-------------|
| `npx @deepseek-ai/dsh web` (npm install) | **Form C** (recommended) or Form A |
| Source checkout (`git clone` + run yourself) | Form C / A / B all work |

**Why is Form C recommended?**

Form C is DSH's official **standard third-party plugin distribution** — a single npm "composition bundle" that users install with `dsh plugin add`, with **no source checkout, no editing of built-in packages, and no Creator mode**. It uses `ctx.connection.rpc` (a Client→Host channel available to third parties) instead of the first-class `@Remote`/api-remotes used by Form B.

**Why was Form B downgraded**: it relies on the first-class `@Remote` + api-remotes mechanism, which requires modifying DSH's built-in `api-remotes` to mount contributions. Third-party plugins cannot do that, so it serves only as a reference for "built-in plugins merged into the monorepo" and is not suitable for community distribution.

## Form C: Standard bundle (⭐ Recommended)

DSH's official **standard third-party plugin distribution**: a single npm package (composition bundle) that users install with `dsh plugin add` — **no source checkout, no editing of built-in packages, no Creator mode**.

> 🚀 **This form is already distributed standalone**: [dsh-dir-tree](https://github.com/bentong-chain/dsh-dir-tree) (published on npm, screenshots/docs/install guide included). One command to install:
>
> ```sh
> dsh plugin --profile web add dsh-dir-tree
> ```

### How it works

- The Host half registers a **third-party RPC channel** via `ctx.connection.rpc.handle('/dirtree', ...)` (no api-remotes, no Typert code generation)
- The Client half calls the Host with `ctx.connection.rpc.call('/dirtree', 'list', { path: cwd })`
- The current workspace `cwd` is read by the Client half from `ctx.sessions.list.getSnapshot().byId[current].cwd` and passed to the Host (no session identity parsing needed on the Host)

### File structure (`bundle/`)

```
bundle/
├── package.json       # dsh.bundle + dsh.client + prepare build script
├── cordis.patch.yml   # inserts the plugin row
├── index.js           # Host half (connection.rpc.handle + node:fs directory listing)
├── client.js          # Client half source (floating UI + connection.rpc.call)
├── client.bundle.js   # build output (generated by prepare)
└── build.mjs          # prepare script: esbuild bundling of client.js
```

### Installation

**Option 1: Install from npm (recommended — no authorization needed)**

This form is published on npm, one command:

```sh
dsh plugin --profile web add dsh-dir-tree
```

**Option 2: Install from git (no npm publish involved)**

```sh
dsh plugin --profile web add github:bentong-chain/dsh-dir-tree
```

On first install you'll be prompted to add an `allowBuilds` authorization to `pnpm-workspace.yaml` in your profile — copy and paste it as prompted.

### How it works under the hood

1. The Host half registers the `/dirtree` RPC channel and lists directories with `node:fs`'s `readdir({ withFileTypes: true })`
2. The Client half reads the current session's `cwd` and calls `connection.rpc.call('/dirtree', 'list', { path: cwd })` to get the tree
3. The floating window renders; clicking `▶` lazily calls again for the subdirectory

> Note: this form is based on research into the DSH source; the `connection.rpc` API is confirmed. For the `build.mjs` esbuild details, verify against the official `turtle-ui` example. Session identity is not part of the RPC channel — the Client half explicitly passing `cwd` is the simplest and most correct approach.

## Form A: Dynamic plugin (most portable)

Self-contained code that any DSH user can run directly — **no checkout, no build**.

### Prerequisites

1. `cordis_define` / `cordis_run` are **built-in model tools of DSH**, invoked by the AI agent in the conversation (not clicked manually). So "installing" means "handing the code to the agent".
2. ⚠️ **These two tools are only available in Creator mode (`cordis` preset)**. They don't exist in the `standard`, `code` (PTC), or `minimal` presets — and **a session's preset is fixed once created; it cannot be switched mid-way**.
3. So before installing, make sure the current session is in Creator mode; if not, **create a new session and choose "Creator mode"**, then install in that new session.

> How to check/switch: open **Settings → Agent Presets** to see the current preset; when creating a new session choose Creator mode (`cordis`). A running session keeps the preset it was created with.

### Installation steps

**Option 1: Paste the code directly (most universal)**

1. Open `dynamic/host.js` and `dynamic/client.js`, and copy the full content of both files.
2. Paste the following into the DSH chat input and fill in both code blocks:

   ```
   Please install this directory-tree dynamic plugin with cordis_define + cordis_run:

   Host code (code.host):
   <paste all of dynamic/host.js>

   Client code (code.client):
   <paste all of dynamic/client.js>
   ```

3. After sending, the agent automatically calls `cordis_define` (submitting host + client together; `idPrefix` is auto-assigned, e.g. `dirt`) and then `cordis_run` to activate.
4. The first time client code activates, an **approval request** pops up — click **Allow / Approve**.
5. The "📁 Current Workspace" floating window appears in the bottom-right corner with the tree loaded.

**Option 2: Let the agent read the files (when the repo is cloned locally)**

If the repository is already cloned locally, just tell the agent:

```
Read dynamic/host.js and dynamic/client.js and install them as a dynamic plugin with cordis_define + cordis_run
```

The agent reads the files, submits, and runs them itself — no manual copy/paste needed.

### Usage

- Click the `▶` of a folder to expand children (lazy loading)
- Drag files/folders into the chat box; the full path is filled in automatically
- Double-click to copy a path; use the search box to filter file names
- Click `−` or `×` to minimize; restore via the blue "📁 Directory Tree" button in the bottom-right corner

### Notes and FAQ

- **You must reinstall after restarting DSH** (dynamic plugins live only in process memory) — repeat the steps above.
- The dynamic plugin shows the first workspace in `workspaceRegistry` (the most recently created one); for **precise tracking of the current session's workspace**, use Form B.

| Symptom | Cause | Fix |
|------|------|------|
| Stuck at "⏳ Loading" | Remote call failed without an error | Have the agent check diagnostics with `cordis_inspect_self` |
| "awaiting user approval" | Waiting for approval | Click Allow |
| The floating window is gone | `−` or `×` was clicked | Click the blue "📁 Directory Tree" button in the bottom-right corner to restore |
| Gone after restart | Dynamic plugins are not persistent | Reinstall, or switch to Form B |

## Form B: Persistent plugin (standard)

Split into two packages (aligned with DSH's official goal architecture of domain package + UI package):

- `@deepseek-ai/dsh-dir-tree` (**domain package**, `persistent/domain/`): Host `DirTreeService` + `@Remote` service, reads `agent.session.header.cwd` for the precise **current-session workspace**
- `@deepseek-ai/dsh-client-ui-dir-tree` (**UI package**, `persistent/ui/`): client floating-window UI
- api-remotes mounts `dirTreeRemote` (provides the `remote.dirTree` namespace)

### Prerequisites

You need access to a DSH source checkout (because compilation + Typert code generation are required).

### Installation steps

1. **Place the source**: put the files under `persistent/domain/` into `packages/dir-tree/dir-tree/` of the DSH checkout, and `persistent/ui/` into `packages/client/ui-dir-tree/`. Which `src/` subdirectory each file maps to is documented in `persistent/README.md`.

2. **Patch api-remotes**: follow `persistent/API_REMOTES_PATCH.md` to modify the 3 files in `packages/api/remotes/` and mount `dirTreeRemote`.

3. **Register tsconfig references**:
   - Root `tsconfig.host.json` `references`: add `{ "path": "./packages/dir-tree/dir-tree/tsconfig.host.json" }`
   - Root `tsconfig.client.json` `references`: add `{ "path": "./packages/client/ui-dir-tree" }`

4. **Build**:

   ```bash
   pnpm install
   pnpm run build:lib:host     # tsc -b + tsdown (includes Typert code generation)
   pnpm run build:lib:client
   ```

5. **Link the packages** (if DSH's `require.resolve` can't find them, create Junction/symlinks manually):

   ```
   apps/cli/node_modules/@deepseek-ai/dsh-dir-tree        → packages/dir-tree/dir-tree
   apps/cli/node_modules/@deepseek-ai/dsh-client-ui-dir-tree → packages/client/ui-dir-tree
   $DSH_HOME/profiles/node_modules/@deepseek-ai/...       → apps/cli/node_modules/@deepseek-ai/...
   ```

6. **Register in the host composition**: edit `$DSH_HOME/profiles/<profile>/cordis.patch.yml`:

   ```yaml
   - insert:
       - id: dir-tree
         name: '@deepseek-ai/dsh-dir-tree'
       - id: ui-dir-tree
         name: '@deepseek-ai/dsh-client-ui-dir-tree'
   ```

7. **Restart DSH** → the floating window appears in the bottom-right corner and follows workspace switches automatically.

### Why Form B tracks the workspace precisely

The `@Remote` method of the domain package takes `agent: Agent` as its first parameter (resolved by the gateway from the browser session identity) and uses `agent.session.header.cwd` to get the **current session's** workspace. Each session mounts its own instance, so switching workspaces switches to the matching session and the tree follows automatically.

### Notes

- Both packages are currently `private: true` with version `0.1.0`; to publish to npm or pass DSH's full release gates (`check-workspace-constraints` / `verify-package-invariants`), you need to add an `invariant` companion package, `publishConfig`, `repository` (mirroring `packages/client/ui-goal`), and align the version numbers.

## Technical Notes

- **Directory detection**: `FsDirEntry.isDirectory` is a getter and unreliable (`!!` can also fail); calling `fs.stat`/`fs.listDir` per entry would hang on large directories. So a **filename heuristic** (no `.` → directory) + **lazy loading** (list one level at a time, recurse on expand) is used.
- **JSON safety**: file nodes have no `children` field (`undefined` is not valid JSON); directory nodes have `children: []`.
- **Form B RPC**: `@Remote` Service + Typert code generation (produces `typert.host.js` / `typert.remote-client.js`); the client calls it via `ctx.remote.dirTree.listTree(sessionId, {})`.
